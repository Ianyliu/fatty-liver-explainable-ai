# Prospective P0 protocol and complete-patient methods study

This specifies a prospective comparison, not reproduction of historical coefficients. No P0 or cohort-scale job has run. The ten-patient input/pipeline gate applies to the planned cohort comparison. A separately labeled one-patient methods study may validate the runner, independent-mask fidelity and deletion calculations while image recovery is investigated; it does not establish patient-level generalization. Additional seeds remain repeated measurements of the same patient. Record the final protocol and source hashes before examining comparative results.

Use the same eligible positive / >=20-image cohort, split09 graph checkpoint, DenseNet121 weights, preprocessing, correlation-based graph construction, class-1 probability target, fixed-alpha Ridge surrogate and patient/seed pairs for both sampling strategies. Start with seeds 0, 1 and 2. Preserve patient-level results; do not treat a patient's perturbations as independent subjects. These prospective choices differ from the historical hard-label RidgeClassifierCV/bootstrap workflow.

## Sampling comparison

The primary comparison should use 1,000 training perturbations per strategy and clearly report all model calls, including full-patient validation and singleton probes. It holds the number of surrogate training rows fixed, rather than claiming equal inference cost. Duplicate masks consume the budget and are reported; they are retained with their multiplicity in this prospective fixed-row comparison. The adaptive sampler's 0.5 predicted-class target, 0.85/0.15 pool bias, exact subset-size rule and one-pool fallback must be recorded with achieved class counts.

Report an additional comparison with a fixed total inference-call budget if making computational-efficiency claims. Subtract the actually measured baseline/validation/singleton overhead from each strategy's available perturbation calls; never give adaptive sampling free probes. Avoid silently removing or caching model calls in only one arm. Timing comparisons require the same allocated GPU and resource settings; the current single smoke timings are not evidence that either method is faster.

For each patient/seed, generate 200 independent random evaluation draws using a separate documented RNG stream. Independent draws can repeat masks or overlap training, especially full and almost-full subsets. Use exactly the same evaluation masks for both fitted surrogates, never fit on evaluation responses, and flag overlap with each training arm. Primary fidelity is probability MAE on the shared evaluation rows whose masks appeared in neither training arm. Also report all-draw MAE, RMSE, thresholded class agreement and GNN class support. Retain draw multiplicity. Report the novel row count and subset-size distribution: filtering changes the estimand and can exclude large subsets. An empty shared-novel set means the primary diagnostic is unavailable.

Sample subset size uniformly from 3 through the patient's image count, then select images without replacement. Evaluation queries are a separate, shared cost. Compare each surrogate with a constant predictor set to its own training-mean GNN probability, without fitting that baseline to evaluation outcomes. Flag one-class evaluations; do not interpret high class agreement alone as strong fidelity. Ridge outputs are unconstrained scores and can lie outside [0,1]; preserve raw outputs and report that occurrence instead of silently clipping. Training uses `RandomState(seed)` for each arm. Evaluation and random-deletion seeds are derived separately with `SeedSequence([seed, 20261007, tag])`, using tags 1 and 2 respectively; record the resulting integers in the plan.

Report results per patient and seed, then summarize paired differences across patients. Inspect missing/failed patients and achieved class support before aggregation. Do not choose a strategy from the single patient's current 20-mask smoke.

## Deletion comparison

Delete image nodes in descending signed class-1 Ridge coefficient order, with ascending-coefficient and seeded random order controls. Use fixed, documented image-ID tie-breaking. Rebuild features/edges through the same loader on every retained subset; the intervention removes nodes rather than zeroing features in an unchanged graph.

Evaluate deletion fractions 0, 0.1, 0.2, 0.3, 0.4 and 0.5, retaining at least three nodes. Record actual deleted/retained counts and evaluate each unique retained count once when rounding produces duplicates. Report the class-1 probability trajectory, its change from the full graph, and the area under the deletion curve using actual deletion fractions. A lower class-1 trajectory is the intended direction for deleting the largest positive class-1 coefficients; it is not an assertion that every patient's curve must be monotonic. Keep patient/seed/control outcomes inspectable.

The original prediction is one shared call reused as the zero-deletion baseline. One seeded random deletion order/control curve is shared between arms; query it once and show it alongside each arm. All other requested masks, including duplicates, receive fresh inference through the uploaded loader. With 20 images, 1,000 training draws per arm, 200 shared evaluation draws and five nonzero deletion steps per curve, each seed consumes 2,247 calls: original 1, random training 1,000, adaptive constructor validation 1, adaptive singleton probes 20, adaptive training 1,000, shared evaluation 200, shared random deletion 5 and four ranked deletion curves with 5 calls each. This study compares equal training-row budgets, not equal total inference budgets.

Bootstrap significance, historical coefficient replay, clustering ablations and full 135-patient expansion are later tasks. They require their own source/runtime reconciliation, missing-image completion and methodology checks; this proposal does not resolve the documented historical uncertainty formulas.
